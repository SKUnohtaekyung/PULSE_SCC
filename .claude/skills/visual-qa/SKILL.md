# visual-qa — UI 렌더링 검증

목적: **화면을 실제로 보고** 판정한다. `lint PASS` + `build PASS` 는 UI 완료 근거가 아니다.

## 0. 전제

현재 스택이 미확정이라 dev 서버 실행 명령이 없다. 렌더링 환경이 준비되지 않았으면 **PASS를 만들어내지 말고** "렌더링 환경 없음 — 시각 검증 미실행"이라고 보고한다.

스택 확정 후:
- Claude Code: `.claude/launch.json` 에 dev 서버를 등록하고 Browser 미리보기로 확인한다
- Codex: 사용 가능한 브라우저 도구로 동일한 화면을 확인한다

## 1. 기준 확인 (렌더링 전)

1. 관련 PRD의 Acceptance Criteria — `docs/product/PRD.md`
2. 디자인 원칙 — `docs/design/DESIGN_SYSTEM.md`
3. 기존 UI 컴포넌트·토큰 (코드) — 새로 만든 것이 기존과 중복되지 않는지

## 2. 렌더링 확인

| # | 항목 | 확인 내용 |
|---|---|---|
| 1 | 화면 렌더링 | 에러 없이 뜨는가. 콘솔 에러가 있는가 |
| 2 | Desktop | 넓은 뷰포트에서 레이아웃이 의도대로인가 |
| 3 | Mobile | 좁은 뷰포트에서 깨지지 않는가 |
| 4 | Breakpoint | 정의된 중단점 전후로 자연스럽게 전환되는가 |
| 5 | Overflow | 가로 스크롤이 생기지 않는가. 긴 텍스트·긴 목록에서 넘치지 않는가 |
| 6 | 타이포 위계 | 제목·본문·보조 텍스트의 크기·굵기 위계가 구분되는가 |
| 7 | Spacing / Token | 하드코딩 값 없이 토큰을 쓰는가. 간격이 일관적인가 |

## 3. 상태 확인

| # | 상태 | 확인 내용 |
|---|---|---|
| 8 | Loading | 로딩 표시가 있는가. 레이아웃이 튀지 않는가 |
| 9 | Empty | 데이터가 없을 때 빈 화면이 아니라 안내가 나오는가 |
| 10 | Error | 실패 시 사용자가 이해할 수 있는 메시지가 나오는가 |
| 11 | Disabled | 비활성 상태가 시각적으로 구분되고 조작이 막히는가 |
| 12 | Hover / Focus | 포인터와 키보드 양쪽에서 상태가 보이는가 |

## 4. 접근성 기본

| # | 항목 |
|---|---|
| 13 | 키보드만으로 주요 흐름을 완료할 수 있는가 |
| 14 | 포커스 링이 보이는가 (제거하지 않았는가) |
| 15 | 이미지·아이콘 버튼에 대체 텍스트/레이블이 있는가 |
| 16 | 텍스트 대비가 읽을 수 있는 수준인가 |
| 17 | 폼 입력에 label이 연결되어 있는가 |

## 5. Visual regression

스냅샷 도구가 프로젝트에 설정되어 있으면 실행한다. 없으면 `도구 없음` 으로 기록한다. **없는 도구를 실행했다고 쓰지 않는다.**

## 6. 판정

```
판정: PASS | FAIL | 미실행(사유)

[확인 방법]
렌더링: <어떻게 확인했는가 — 실제 URL/뷰포트>

[FAIL 항목]
- <항목 번호> <무엇이 어떻게 잘못 보이는가>

[확인하지 못한 항목]
- <번호> : <이유>
```

한 항목이라도 FAIL이면 전체 FAIL이다. 원인을 분석해 최소 수정 후 실패 항목부터 재확인한다.
