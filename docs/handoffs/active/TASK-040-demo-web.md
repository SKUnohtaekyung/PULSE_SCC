## Decisions
- **별도 폴더 복제**: 디자인을 크게 바꿔도 Android 앱 계약·검증 이력이 흔들리지 않게 한다. 대가로 원본 변경은 수동으로 옮겨야 한다.
- **전송 계층에서 목 교체**: `sendRequest` 한 곳만 바꿔 화면·`ApiClient`의 토큰 갱신·오류 처리 경로를 그대로 탄다.
- **결과 가게 고정**: 입력과 관계없이 결과는 예시 가게 '온기 한식당'이다. 지어낸 리뷰가 실존 가게 이름에 붙는 것을 막는다(독립 리뷰 1차 High).
- **"앱 그 자체"**(사용자 결정): 소개 페이지 없이 앱만, PC는 가운데 휴대폰 폭. 그래서 DESIGN_SYSTEM §7의 넓은 화면 배치(1024px 이상 960·2열)는 쓰지 않는다. 폭 판단은 `useAppWidth`(최대 430) 한 곳으로 모았다.
- **발표 시안 우선**(사용자 결정): DESIGN_SYSTEM의 이전 결정(분석 기준 맨 아래, 관점 카드 해석 첫머리, 첫 탭 "분석 결과" 등)과 다르게 배치했다. 전체 목록은 README 표. 원본 앱과 DESIGN_SYSTEM은 그대로다.
- **시연 표시는 상시 띠 대신 자리별 한 줄**(사용자 결정 — 시안과 같게). 로그인·가게 입력·결과 기준 카드·리뷰 출처 줄·그림 고지에 남겼다.
- **맥박은 앱 시작·분석 대기에만**(사용자 결정). 둘 다 기다리는 동안의 로딩 표시라 되풀이한다. 로그인에서는 뺐다.
- **입력 칸은 시안의 테두리 없는 회색 칸으로 바꾸지 않음**: 칸 경계 3:1 대비(DESIGN_SYSTEM §8, WCAG 1.4.11) 때문이다.
- **"먼저 볼 것" 아이콘 색은 컴포넌트에서**: 시안의 남색 칸 위 흰 아이콘을 토큰(`colors.perspective.priority`)에 넣으면 `verify:tokens`의 "강조선 / 카드" 검사(흰색 1:1)가 실패한다. 강조선은 시연 앱에서 쓰지 않으므로 토큰은 그대로 두고 `PerspectiveCard`에서 `colors.brand.*`로 칠한다.
- **결과 화면 나누기**(사용자 결정): 한 화면 긴 스크롤 대신 실제 앱처럼 누르면 넘어가게. PRD FR-002(선택한 유형 아래 4관점 모두, 대표 근거 기본 노출) 때문에 관점은 손님 유형 화면 한 장에 압축해 두고 따로 쪼개지 않았다. 원본 앱은 미리보기에서 다른 화면으로 나가지 않지만(SCREEN_STATES §7) 시연 앱은 jobId로 하위 화면을 연다.
- **이름 짧게**: 단상 칸(약 110px)에서 "평일 점심 한 끼 손님"이 글자 중간에서 끊겨 짧게 줄였다.
- **Remotion 라이선스 미확인**: 팀이 무료 대상인지 확인하지 않아 `acknowledgeRemotionLicense`를 넣지 않았다.
