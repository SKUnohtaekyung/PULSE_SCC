# ADR-004 — MVP 리뷰 출처를 네이버로 한정

| | |
|---|---|
| Status | Accepted |
| Date | 2026-09-12 |
| 결정자 | 팀 (`role:product`) |
| 관련 요구사항 | [PRD.md](../product/PRD.md) FR-001 |

## Context

[ADR-002](ADR-002-review-collection.md)는 네이버 지도와 카카오맵의 공개 리뷰를 브라우저 자동화로 수집하는 결정을 기록했다. 그러나 두 플랫폼을 동시에 지원하면 수집기 구현·변경 대응·실패 처리·검증 범위가 함께 늘어난다. 1차 MVP는 분석 가치 검증에 집중하기 위해 리뷰 출처를 더 좁힐 필요가 있다.

## Decision

**1차 MVP에서는 사용자가 등록한 네이버 가게 URL의 네이버 공개 리뷰만 수집·분석한다. 카카오맵 리뷰는 수집하거나 분석하지 않는다.**

- 입력 URL은 구현 전에 확정한 네이버 허용 도메인 목록으로 검증한다.
- 분석 계층은 특정 플랫폼을 알지 않게 유지하고, 수집 계층은 향후 다른 출처를 추가할 수 있는 인터페이스로 분리한다.
- 수집 방식과 개인정보 최소화·빈도 제한·재검토 조건은 ADR-002를 계속 따른다.

## Reason

- 수집기와 검증 범위를 줄여 MVP의 핵심인 `리뷰 → 고객 이해 → 실행 제안` 검증에 집중할 수 있다.
- 입력 화면에서 하나의 플랫폼만 안내하므로 사용자 혼동과 잘못된 URL 입력을 줄일 수 있다.
- 이 범위 축소는 네이버 자동 수집의 이용약관·차단·민사 위험을 해결하지 않는다. 위험은 ADR-002에 기록된 상태로 남는다.

## Alternatives Considered

| 대안 | 채택하지 않은 이유 |
|---|---|
| 네이버와 카카오를 동시에 지원 | MVP 수집·테스트·운영 범위가 커진다 |
| 카카오만 지원 | 팀이 1차 분석 출처로 네이버를 선택했다 |
| 사용자가 리뷰 파일을 직접 업로드 | 현재 정한 `네이버 가게 URL 입력 → 자동 수집` 흐름과 다르다. 자동 수집 경로 재검토 시 대안으로 남긴다 |

## Consequences

**쉬워지는 것**

- 플랫폼별 UI 분기와 카카오 수집기 구현이 MVP에서 빠진다.
- 수집 실패와 URL 검증 테스트를 네이버 범위에 집중할 수 있다.

**어려워지는 것 / 감수하는 것**

- 카카오에만 존재하거나 카카오에서 더 활발한 리뷰는 분석에 포함되지 않는다.
- 결과를 플랫폼 전체 고객 의견으로 일반화할 수 없다.
- 향후 카카오를 추가하려면 별도 제품 결정과 수집 정책 재검토가 필요하다.

## Revisit Trigger

- 네이버 리뷰만으로 사용자 검증에 필요한 품질이나 표본 수를 확보하지 못할 때
- 카카오 지원 요구가 사용자 인터뷰에서 반복 확인될 때
- 자동 수집 방식 자체를 계정 연동·파일 업로드·제휴 방식으로 전환할 때
