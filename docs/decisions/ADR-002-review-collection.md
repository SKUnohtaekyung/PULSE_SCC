# ADR-002 — 리뷰 데이터 수집 경로

| | |
|---|---|
| Status | Accepted |
| Date | 2026-08-23 |
| 결정자 | 팀 (`role:product` 제안, 팀 확인) |
| 관련 이슈 | #3 [SPEC] 리뷰 데이터 수집 경로 확정 (ADR) |

## Context

이 제품의 원재료는 네이버 지도·카카오맵에 공개된 가게 리뷰다([PRD.md](../product/PRD.md) FR-001). 수집 경로를 정하지 않으면 제품이 성립하지 않는다.

조사 결과 확인된 사실:

| 확인 항목 | 내용 |
|---|---|
| 네이버 지도 robots.txt | 최상단에 *"BOT ACCESS FOR THE PURPOSES OF AI TRAINING AND RETRIEVAL-AUGMENTED GENERATION (RAG) IS STRICTLY PROHIBITED"* 를 명시. ClaudeBot·GPTBot 등을 개별 차단하고 전 경로에 `Disallow: /` 적용 |
| 카카오맵 robots.txt | 동일한 AI·RAG 금지 문구 및 전 경로 차단 |
| 네이버 이용약관 | 자동화 수단에 의한 게시물 수집 금지 |
| 카카오 공식 답변 | 리뷰를 오픈API·제휴 어느 쪽으로도 제공하지 않음 |

근거 원문과 등급은 [PROBLEM_BASELINE.md §2.5](../product/PROBLEM_BASELINE.md) 및 `research/digital_competitors.md` 에 있다.

즉 **공식적으로 열려 있는 자동 수집 경로는 없다.** 이 상태에서 결정이 필요했다.

## Decision

**MVP 단계에서 Playwright 등 브라우저 자동화로 네이버 지도·카카오맵의 공개 리뷰를 수집한다.**

## Reason

팀이 2026-08-23에 선택한 방향이다. 판단 근거는 다음과 같다.

- MVP의 목적은 `리뷰 → 고객 이해 → 실행 제안` 한 줄이 실제로 유용한지 **빠르게 확인**하는 것이다. 수집 계층을 먼저 정교하게 만들면 검증이 늦어진다.
- 대안 중 가장 안전한 사장님 계정 연동 방식은 구현 난이도가 높아 MVP 범위를 키운다.
- 수집 대상은 **로그인 없이 볼 수 있는 공개 리뷰**이며 개인 식별정보를 저장하지 않는다.

**이 결정이 위 Context의 사실을 바꾸지는 않는다.** robots.txt와 이용약관은 그대로이며, 이 방식은 그 문서들이 금지한 행위에 해당한다. 팀은 그 점을 알고 선택했다.

## Alternatives Considered

| 대안 | 채택하지 않은 이유 |
|---|---|
| 사장님 본인 계정 연동 후 본인 가게 리뷰만 수집 | 법적으로 가장 깨끗하고 차별점도 되지만 구현 난이도가 높아 MVP가 커진다. **2단계 이후 전환 후보로 남긴다** |
| 공식 API·제휴 | 카카오는 제공하지 않는다고 공식 답변했다. 네이버도 해당 API 없음 |
| 약관을 준수한 소량 수기 수집 | 검증에는 쓸 수 있으나 제품 기능으로 성립하지 않는다 |
| 공개 데이터셋 | 국내 음식점 리뷰의 최신·매장 단위 공개 데이터셋을 찾지 못했다 |
| 예시 데이터만 사용 | 실제 사장님이 자기 가게 결과를 보는 검증이 불가능해진다 |

## Consequences

**쉬워지는 것**

- 수집 계층을 빠르게 만들 수 있고 MVP 배포 일정이 앞당겨진다.
- 사장님에게 계정 연동을 요구하지 않아 진입 장벽이 낮게 유지된다([PRD.md](../product/PRD.md) §6).

**어려워지는 것 / 감수하는 위험**

| 위험 | 성격 |
|---|---|
| 플랫폼 이용약관 위반 상태 | 계정·IP 차단, 서비스 중단 요구가 발생할 수 있다 |
| 대외 발표 시 질문 | 중간간담회를 포함해 이 지점을 질문받을 가능성이 높다. 답변을 준비해야 한다 |
| 수집 안정성 | 페이지 구조 변경 시 수집이 깨진다. 유지보수 부담이 지속된다 |
| 확장 시 재검토 필수 | 유료화·외부 공개·투자 유치 등 사업화 단계로 가면 이 방식은 유지할 수 없다 |

**지켜야 할 것**

1. **공개 리뷰만 수집한다.** 로그인이 필요한 영역에 접근하지 않는다.
2. **리뷰 작성자 식별정보를 저장·표시하지 않는다.**
3. 수집 빈도를 필요한 만큼으로 제한한다. 대량·상시 크롤링을 하지 않는다.
4. **수집 시점과 건수를 사용자에게 표시한다**([PRD.md](../product/PRD.md) §10 FR-001).
5. 발표·문서에서 수집 방식을 사실대로 적는다. 공식 API를 쓰는 것처럼 표현하지 않는다.

**되돌리려면**

사장님 계정 연동 방식으로 전환한다. 수집 계층만 교체하면 되도록 분석·제안 계층과 분리해 설계한다. 이 분리를 지켜두는 것이 이 결정의 전제다.

**재검토 시점** — 1단계 MVP 검증 종료 시, 또는 플랫폼으로부터 차단·이의 제기를 받은 시점.
