# ADR-005 — 계정당 분석 저장 1개와 세션 한정 결과

| | |
|---|---|
| Status | Accepted |
| Date | 2026-09-13 |
| 결정자 | 팀 (`role:product`) |
| 관련 요구사항 | [PRD.md](../product/PRD.md) FR-011 |

## Context

사용자는 가게 분석을 반복 실행할 수 있어야 하지만, MVP에서 복수 가게·분석 이력을 영구 관리하면 저장·목록·교체·비교 기능까지 범위가 커진다. 계정에 남길 분석과 일회성 분석을 구분할 필요가 있다.

## Decision

- 한 계정에는 **저장된 가게 분석 결과를 최대 1개**만 둔다.
- 저장본이 이미 있어도 다른 가게 또는 같은 가게의 새 분석을 실행할 수 있다.
- 저장 슬롯이 찬 상태에서 생성한 결과는 추가 저장할 수 없는 **일회성 결과**다.
- 일회성 결과는 현재 인증 세션에 귀속한다. 사용자가 로그아웃 후 다시 로그인하거나 다른 새 로그인 세션이 시작되면 분석·리뷰·페르소나 이미지 등 해당 결과의 파생 데이터를 함께 삭제하고 조회할 수 없게 한다.
- 앱이 재실행돼도 기존 인증 세션이 안전하게 복원된 경우에는 새 로그인으로 보지 않는다.
- 데이터베이스는 계정당 저장본이 1개를 넘지 않도록 서버 검증과 고유 제약으로 보장한다.

## Consequences

**가능해지는 것**

- 사용자는 저장 슬롯이 차 있어도 추가 분석을 시험할 수 있다.
- MVP에서 복수 저장 목록과 월별 이력 관리를 만들지 않아도 된다.

**필요한 것**

- 저장 결과와 일회성 결과를 구분하는 데이터 모델과 권한 검증
- 동시에 들어온 저장 요청에서도 1개 제한을 지키는 트랜잭션·고유 제약
- 새 로그인 세션 생성 시 이전 세션의 일회성 결과 삭제
- 재로그인이 발생하지 않는 경우를 위한 최대 보관 시간과 정리 작업

## Open Questions

- 첫 분석을 자동 저장할지, 사용자가 명시적으로 저장할지
- 사용자가 저장본을 삭제하거나 새 분석으로 교체할 수 있는지
- 한 계정의 동시 분석 작업 수 제한
- 일회성 결과의 최대 보관 시간
