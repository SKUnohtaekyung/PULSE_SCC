## 0. 가장 먼저 읽을 요약

### SCC는 무엇인가

SCC는 성결대학교 교수학습지원센터가 운영하는 **창의문제해결 프로젝트(Sungkyul Creative Challenge)**다. 학생들이 팀을 이루어 일상·학교·지역사회·사회 문제를 선정하고, 협력적으로 해결방안을 탐색한 뒤 자유 형식의 결과물을 만드는 15주 심화형 팀 프로젝트다. 단순 아이디어 발표나 창업경진대회라기보다 `문제 발견 → 조사 → 협업 → 구현 → 검증 → 개선 → 결과 공유`를 중시하는 교육형 프로그램이며, 최종에는 실제 산출물의 완성도와 효과도 요구된다.

### F12는 무엇을 하는가

F12의 최신 공식 프로젝트명은 **「AI 리뷰 분석 기반 안양 소상공인 디지털 격차 해소 프로젝트」**다. 안양 만안구·명학역 인근 영세 외식업 소상공인이 리뷰를 쉽게 이해하고 홍보 행동까지 이어가도록 돕는 시연 가능한 웹 프로토타입을 만든다. 공식 신청서상 최종 흐름은 다음과 같다.

`손님 이해(리뷰 분석) → 홍보영상 제작 → 지역 인플루언서 확산`

### 기존 PULSE와 SCC의 관계

PULSE는 SCC 이전부터 기획된 **외식업 사장님용 통합 마케팅 자동화 졸업작품**이다. PULSE 전체 제품은 손님·상권 분석, 영상 제작, 가게 현황, 리뷰 관리, 인플루언서 협찬 등 넓은 범위를 가진다. SCC는 이 전체 제품을 그대로 새로 만드는 활동이 아니라, 기존 기술·화면을 출발점으로 삼아 **안양 지역 소상공인 문제에 적용하고 현장에서 검증·개선하는 별도 지역 문제해결 활동**으로 설명해야 한다.

### 폴더에서 확인되는 최신 진행상태

가장 최신 진행자료는 2026-07-03의 `SCC_F12_추가자료제출.docx`다.

- 전체 진행률: 약 35%라고 제출
- 손님 분석: 개발 완료라고 제출
- 홍보영상: UI/UX 초안과 영상 프롬프트 설계 완료, 기능 개발 준비 중
- 인플루언서 매칭: 진행 전
- 안양 상권조사·소상공인 인터뷰: 프로그램 기간 중 수행 예정

단, 이 상태는 현재 기준 7주 이상 지난 **프로그램 시작 전 기준선**이다. 현재 폴더에는 7월 3일 이후의 코드, 화면, 인터뷰, 리뷰 원데이터, 멘토 회의록, 사용성 테스트 기록이 없다. 따라서 이 문서만으로 8월 21일 현재 실제 진행률을 확정할 수 없다.

## 2. SCC 프로그램 개요

### 2.1 기본 정보

- 정식 명칭: 창의문제해결 프로젝트(Sungkyul Creative Challenge, SCC)
- 상위 맥락: 2026 미래형 창의·융합 역량 개발, 성결대학교 대학혁신지원사업
- 운영: 성결대학교 교수학습지원센터
- 성격: 학생 주도 심화형 팀 문제해결 프로젝트
- 활동 기간: 2026년 7월~10월, 총 15주
- 주제: 자유
- 결과물: 웹·앱, VR·AR, 영상, 교육 프로그램, 정책 제안서, 연구보고서, 디자인 시안, 기획안, 시제품, 게임 등 자유

### 2.2 주제 탐색 범위

공식 포스터는 다음 문제 유형을 예시로 든다.

1. 일상생활에서 반복되는 불편이나 비효율
2. 수업·시설 등 학교생활에서 개선이 필요한 부분
3. 안전·환경·편의시설·공공서비스 등 지역사회 문제
4. 환경·안전·복지 등 사회적 이슈
5. 자동화·정보 제공·예측·맞춤형 서비스 등 AI·디지털 기술로 해결 가능한 문제

F12는 이 가운데 **지역사회 문제 + AI·디지털 기술 + 소상공인 디지털 격차**의 결합으로 이해할 수 있다.

### 2.3 참여 조건과 운영상 주의

- 참여 대상: 성결대학교 재학생
- 팀 구성: 재학생 3~5명 권장
- 멘토: 교수 또는 외부 전문가 1명 필수
- 프로그램 종료 전 군입대·휴학·해외체류 예정자는 참여 불가
- 동일 프로젝트로 다른 교내 대학혁신지원사업에 참여 중인 팀은 중복 참여 불가
- F12는 최종 신청서에서 교과목·졸업작품 연계 프로젝트로 체크했다.
- 졸업작품 연계 자체가 참여 불가를 뜻하지는 않지만, 정규 교육과정 지도에 대한 멘토 활동비는 제한될 수 있다. 학생 재료비 등은 정상 지원된다고 신청서에 적혀 있다.

## 3. F12 팀과 공식 프로젝트

### 3.1 팀 정체성

F12는 웹사이트에서 F12를 눌렀을 때 숨겨진 코드가 보이는 것처럼, 문제의 진짜 원인을 분석하고 기술로 해결한다는 의미다.

### 3.2 팀 구성과 역할

| 구성원 | 공식 역할 |
|---|---|
| 노태경 | PM·기획 총괄, 안양 만안구 현장조사와 사용성 테스트 설계 |
| 오해서 | 백엔드·검증용 프로토타입 구현 |
| 윤준하 | AI·NLP 리뷰 분석 설계: 키워드·감정·토픽 추출 |
| 김혜린 | 프론트엔드, UX 리서치, 현장 인터뷰·사용성 테스트, 데이터 분석·디자인 |
| 최윤수 | 데이터 수집·정리·자료조사, 리뷰·상권 데이터 라벨링, 디지털 격차 선행사례, 발표자료 정리 |
| 김정이 멘토 | 문제정의·데이터 해석·AI 검증·현장조사·일정·산출물·발표 자문 |

팀 운영 약속은 주 1회 팀 회의, 메신저·공유드라이브를 통한 진행 공유, 일정·제출기한 공동 관리다. 멘토 확인서에는 격주 1회 미팅과 회의록을 통해 피드백 반영 과정을 점검한다고 적혀 있다.

### 3.3 공식 문제 정의

F12가 다루는 문제는 다음 네 층으로 구성된다.

1. 외식 소상공인의 낮은 생존율과 높은 폐업 위험
2. 고객 리뷰를 읽고 활용할 시간·전문지식이 부족한 영세 사장님의 디지털 격차
3. 촬영·편집 기술과 비용 때문에 숏폼 홍보를 지속하기 어려운 문제
4. 성결대·명학역이 위치한 안양 만안구 골목상권의 지역적 취약성

공식 신청서는 이 문제를 활동 초기의 지역 소상공인 인터뷰와 실제 리뷰·상권 데이터 분석으로 검증·구체화한다고 약속했다.

### 3.4 공식 해결책

`손님 이해 → 홍보영상 제작 → 인플루언서 확산`을 한 흐름으로 연결하는 AI 웹앱이다.

#### 기능 1. 손님 분석

- 입력: 온라인 리뷰 텍스트 또는 예시 데이터, 지역 상권 정보
- 처리: 형태소 분석, 키워드·감정·반복 의견 분석, 토픽 군집화, 쉬운 문장형 요약
- 출력: 대표 손님 유형, 핵심 니즈·불편, 고객여정, ‘오늘 해볼 일’ 실행 제안

#### 기능 2. 홍보영상 제작

- 입력: 손님 분석에서 넘어온 타깃·분위기, 음식·매장 사진
- 처리: 스토리보드와 카메라 연출을 담은 영상 프롬프트 구성, Google Veo 3 연동 계획
- 출력: SNS 업로드용 세로형 9:16 숏폼 영상(mp4)

#### 기능 3. 인플루언서 매칭

- 입력: 손님 유형·키워드·업종, 지역 인플루언서 프로필
- 처리: 임베딩 벡터와 코사인 유사도 기반 매칭 계획
- 출력: 매장에 맞는 지역 푸드 인플루언서 추천 목록과 협찬 의뢰 흐름

### 3.5 공식 최종 산출물

## 4. 기존 PULSE 졸업작품과 SCC의 관계

### 4.1 기존 PULSE 제품

PULSE는 외식업 사장님의 마케팅 지식 부족, 시간 부족, 신뢰할 전문가 부족을 해결하기 위해 기획된 범용 B2B 마케팅 자동화 플랫폼이다.

기존 PULSE 기본 루프:

`주변 상권·손님 분석 → 홍보영상 제작 → 가게 현황·다음 행동 → 다시 영상 제작`

기존 PULSE 별도 Pro 루프:

`리뷰 관리·답변 + 인플루언서 협찬 매칭`

기존 PULSE에는 다음과 같은 넓은 범위가 포함된다.

- 상권·손님 분석과 AI 대화형 코칭
- 사진 기반 숏폼 영상 제작
- 날씨·시즌·성과를 이용한 가게 현황 대시보드
- 리뷰 답변 자동화
- 구독·Pro 모델
- 인플루언서 검색·추천·협찬 요청
- 사진 보관함, PULSE Score, 수수료 비교, 다채널 전략 등 확장 기능

### 4.2 SCC용 재정의

SCC 신청 준비 과정에서는 PULSE의 상업적 ‘마케팅 자동화’ 프레임을 다음처럼 재정의했다.

- 대상: 범용 외식업 사장님 → 안양 만안구·명학역 인근 영세 소상공인
- 목적: 마케팅 효율 → 지역 골목상권 자생력과 디지털 격차 완화
- 핵심 검증: 리뷰가 실제로 사장님의 손님 이해와 홍보 행동에 도움이 되는가
- SCC 고유 활동: 지역 상권조사, 소상공인 인터뷰, 안양 데이터 적용, 현장 사용성 테스트, 개선 기록

### 4.3 두 프로젝트를 설명하는 안전한 문장

> PULSE는 졸업작품으로 기획된 전체 마케팅 플랫폼이며, SCC에서는 이를 완성품으로 다시 제출하는 것이 아니라 기존 PoC를 출발점으로 안양 지역 소상공인의 실제 문제에 적용하고 현장에서 검증·개선한다. 최종적으로는 신청서에 약속한 손님 분석·영상 제작·인플루언서 매칭을 단계적으로 연결하되, 중간시점에는 리뷰 인사이트와 실행 제안 흐름을 우선 검증한다.

### 4.4 범위 비교

| 구분 | 기존 PULSE | SCC F12 |
|---|---|---|
| 성격 | 졸업작품·범용 마케팅 SaaS | 지역 문제해결·현장검증 프로젝트 |
| 사용자 | 외식업 사장님 일반 | 안양 지역 영세 외식업 소상공인 |
| 핵심 목적 | 반복 가능한 마케팅 자동화 | 디지털 격차 완화와 지역 현장 검증 |
| 기본 루프 | 분석 → 영상 → 가게 현황 | 분석 → 영상 → 인플루언서 확산 |
| 인플루언서 | 선택형 Pro·BM 기능 | 공식 신청서상 핵심 산출물 |
| SCC 고유 성과 | 해당 없음 | 지역 데이터, 인터뷰, 테스트, 개선 과정 |

## 6. 설계된 제품·기술 구조

> 이 절은 **구현 완료 증명**이 아니라 문서상 설계다.

### 6.1 사용자 흐름

1. 매장 리뷰 또는 예시 데이터를 입력한다.
2. 반복 의견, 긍정·불만, 핵심 키워드와 주제를 분석한다.
3. 대표 손님 유형, 니즈·불편, 고객여정과 실행 제안을 확인한다.
4. 분석 결과의 타깃·분위기를 영상 제작 단계로 넘긴다.
5. 음식·매장 사진을 올려 세로형 홍보영상을 생성한다.
6. 손님 유형·키워드와 맞는 지역 푸드 인플루언서를 추천한다.

### 6.2 기술 아키텍처

- 프론트엔드: React
- 메인 백엔드: Spring Boot
- AI·데이터 서버: FastAPI
- 정형 데이터: MySQL
- 원본 리뷰·분석 로그: MongoDB
- 한국어 형태소 분석: Kiwi
- 토픽 군집화: BERTopic
- 쉬운 문장형 인사이트: LLM과 실제 리뷰 근거 기반 생성(RAG) 계획
- 지역 정보: Kakao Local API 계획
- 영상 생성: Google Veo 3 API 계획

문서상 전체 호출 흐름은 `React → Spring Boot → FastAPI → 외부 AI·데이터 API → 결과 반환`이다.

### 6.3 영상 프롬프트 설계

`pulse/Video.md`는 다음을 설계한다.

- 9:16 세로형, 8~10초 영상
- HOOK 0~3초, BODY 3~7초, OUTRO 7~10초
- 에너지·프리미엄·무드 스타일 매핑
- 업로드된 음식 이미지와 페르소나를 반영
- 생성 모델에는 글자·자막·워터마크를 만들지 않도록 제한

공식 주차 계획에는 ‘자막·템플릿’ 구현이 포함돼 있으므로, 최종 방식은 **Veo 영상 자체에는 텍스트를 생성하지 않고 후처리 단계에서 자막·템플릿을 합성하는지** 확인해야 한다.

### 6.4 데이터 수집 원칙

`pulse/tech.md`는 Playwright로 네이버·카카오 리뷰를 자동 수집하는 구조를 제안하지만, SCC 데이터 전략 문서는 대량 자동수집의 약관·저작권 위험을 경고한다.

안전한 우선순위는 다음과 같다.

1. 사장님 동의를 받은 리뷰 데이터
2. 공식 API와 공개 데이터셋
3. 약관을 준수한 소량 수기 수집
4. 발표용 예시 데이터는 실제 지역 데이터와 명확히 구분

리뷰어 닉네임과 인터뷰 대상 개인정보는 비식별화한다.

## 7. 지역문제 데이터와 주장 가능 범위

### 7.1 현재 자료에서 사용할 수 있는 수치

| 수치 | 의미 | 주의 |
|---|---|---|
| 숙박·음식점업 5년 생존율 20.5% | 외식업의 구조적 취약성 | 전국 단위 |
| 음식업 폐업률 16.2%, 전 업종 9.0% | 음식업 폐업률이 약 1.8배 | 2023년 자료 |
| 폐업 사유 중 사업부진 48.9% | 사업부진이 주요 폐업 사유 | 전국 단위 |
| 소상공인 경영애로 중 상권쇠퇴 37.7% | 상권쇠퇴가 주요 어려움 중 하나 | 2022 조사 |
| 만안구 사업체 14,938개, 동안구 21,047개 | 만안구의 사업체 기반이 상대적으로 작음 | 2025 경제총조사 대상 사업체 |
| 리뷰 항상 확인 80.3% | 리뷰 확인 행동의 보조 근거 | 음식점이 아닌 제품 전반 조사 |

### 7.2 아직 검증되지 않은 핵심 가설

- 안양 만안구 영세 사장님이 실제로 리뷰 활용에 큰 어려움을 겪는가
- 리뷰 인사이트가 실제 운영·홍보 의사결정에 유용한가
- 쉬운 문장형 결과를 디지털에 익숙하지 않은 사장님도 이해할 수 있는가
- 영상·인플루언서 연결이 실제 홍보 행동으로 이어지는가

이 가설은 신청서상 소상공인 인터뷰와 현장 사용성 테스트로 확인해야 한다.

### 7.3 금지하거나 제한해야 할 표현

- 80.3%를 음식점 방문 리뷰 조사라고 표현하지 않는다.
- 만안구 사업체 수가 적다는 사실만으로 상권 침체의 원인·결과를 확정하지 않는다.
- 명학역 상권의 점포 수·폐업률·유동인구는 실제 추출 자료 없이 숫자를 만들지 않는다.
- AI 분석이 매출·재방문율을 높였다고 말하지 않는다.
- 인터뷰 전에는 ‘사장님들이 원한다’가 아니라 ‘검증할 가설’이라고 표현한다.

| 리뷰 수집 | 기술 문서는 Playwright 자동수집, 데이터 전략은 약관 위험 경고 | 동의·공식 API·소량 수집 우선 |
| OT 일정 | PDF는 A·B·C 체크처럼 보임, 최종 HWP는 A·B만 체크 | 최종 HWP 우선 |
| 최윤수 역할 | PDF 역할표에서 불명확, 최종 HWP에 상세 역할 추가 | 최종 HWP 역할 사용 |
| 가산점 | 내부 전략은 학생 성장, 포스터는 다른 학년/복수 학과 | 포스터 문구만 공식 취급 |
| 평가 루브릭 | 내부 문서가 100점 배점표를 공식이라 주장 | 원본 부재, 재확인 전 참고용 |

## 9. 중간발표 맥락

사용자가 제공한 발표 안내 이미지는 다음 항목을 참고 예시로 제시한다.

1. 팀 소개
2. 프로젝트 소개: 기획 배경, 문제와 필요성, 해결 방법
3. 역할 분담
4. 현재까지의 활동: 조사, 인터뷰, 아이디어, 개발 등
5. 현재 고민 또는 어려운 점: 진행 중 어려움, 개선 필요 부분
6. 향후 계획: 남은 활동, 추진 방향, 문제 해결 계획

추가 원칙은 다음과 같다.

- 팀 특성에 맞춰 자유롭게 구성한다.
- 다른 팀도 이해할 수 있도록 전문용어보다 쉽고 명확한 표현을 쓴다.

### F12 중간발표의 안전한 중심 서사

`신청 당시 약속 → 프로그램 시작 전 기준선 → SCC 기간 신규 활동 → 현장에서 배운 점 → 프로토타입 변화 → 현재 어려움 → 후반 검증계획`

### 발표에서 우선 보여줄 증거

- 신청 주차계획 대비 완료·진행·지연 상태
- SCC 이전 자산과 SCC 기간 신규 결과의 구분
- 안양 상권조사와 소상공인 인터뷰의 실제 수량·기록
- 리뷰 데이터의 출처·기간·매장 수·리뷰 수
- 실제 리뷰가 반복 의견·감정·쉬운 문장형 인사이트로 바뀌는 예
- `리뷰 입력 → 인사이트 → 실행 제안` 작동 화면
- 분석 오류 사례와 개선 내용
- 멘토 피드백과 반영 이력
- 후반부 영상·매칭·현장 사용성 테스트 일정

### 기술용어의 발표용 번역

| 기술 표현 | 쉬운 발표 표현 |
|---|---|
| BERTopic | 여러 리뷰에서 반복되는 의견을 주제별로 묶는다 |
| 감정 분석 | 만족과 불만을 구분한다 |
| RAG | 실제 리뷰를 근거로만 요약해 없는 내용을 줄인다 |
| 임베딩·코사인 유사도 | 가게 특성과 잘 맞는 지역 홍보자를 찾는다 |
| LLM | 분석 결과를 사장님이 이해하기 쉬운 문장으로 바꾼다 |

## 11. 다른 문서·프로젝트에서 재사용할 표준 설명

### 프로그램 설명

> Sungkyul Creative Challenge(SCC)는 성결대학교 교수학습지원센터가 운영하는 15주 창의문제해결 팀 프로젝트다. 학생들이 일상·학교·지역사회·사회 문제를 직접 선정하고 조사·협업·구현·검증·개선을 거쳐 자유 형식의 결과물을 만든다.

### F12 프로젝트 설명

> F12는 안양 지역 영세 외식업 소상공인의 디지털 격차를 줄이기 위해, 리뷰에서 손님 유형과 니즈를 쉽게 정리하고 홍보영상 제작과 지역 인플루언서 확산까지 연결하는 웹 프로토타입을 개발·검증한다.

### PULSE와 SCC의 관계 설명

> PULSE는 외식업 사장님을 위한 전체 마케팅 자동화 졸업작품이고, SCC F12는 그 기존 PoC를 안양 지역 문제에 적용해 실제 소상공인 인터뷰·데이터·사용성 테스트로 검증하고 개선하는 별도 활동이다.

### 현재 상태 설명

> 2026년 7월 3일 팀 제출자료 기준 전체 진행률은 약 35%였고, 손님 분석은 완료, 홍보영상은 설계 단계, 인플루언서 매칭과 안양 현장검증은 착수 전으로 보고됐다. 이후 실제 진척은 최신 코드·화면·조사 기록으로 별도 갱신해야 한다.

## 12. 개인정보와 외부 공유 원칙

- 발표·공유본에는 전화번호, 이메일, 학번, 서명 이미지를 넣지 않는다.

- 리뷰어 닉네임과 개인 식별정보는 제거한다.
- Claude Code, ChatGPT, Perplexity, Veo 등 외부 AI 도구에 인터뷰 원문이나 연락처를 그대로 입력하지 않는다.
- 실제 데이터와 예시 데이터는 화면에 명확히 표시한다.

## 14. 문서 갱신 규칙

새 자료가 생기면 다음 순서로 이 문서를 갱신한다.

1. 자료 날짜와 제출 여부를 기록한다.
2. 공식 약속, 팀 제출 주장, 설계, 실제 증빙을 구분한다.
3. 기존 PULSE 자산인지 SCC 기간 신규 결과인지 표시한다.
4. 수치에는 출처·연도·표본 범위를 붙인다.
5. ‘완료’는 코드·화면·데이터·기록 중 최소 하나의 확인 가능한 증거가 있을 때만 사용한다.
6. 인터뷰·테스트 결과는 대상 수와 실제 수행일을 함께 적는다.
7. 충돌이 생기면 최종 HWP와 이후 공식 제출자료를 우선하고, 변경 이유를 남긴다.

이 문서는 현재 폴더의 자료를 통합한 컨텍스트 문서이며, 2026-07-03 이후 실제 진척을 대신하는 문서가 아니다.
