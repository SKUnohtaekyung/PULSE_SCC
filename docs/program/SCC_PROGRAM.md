## 1. 프로그램 개요

| 항목 | 값 |
|---|---|

| 상위 맥락 | 2026 미래형 창의·융합 역량 개발 / 성결대학교 대학혁신지원사업 |

**공식 포스터가 제시한 문제 유형 예시**

1. 일상생활에서 반복되는 불편이나 비효율
2. 수업·시설 등 학교생활에서 개선이 필요한 부분
3. 안전·환경·편의시설·공공서비스 등 지역사회 문제
4. 환경·안전·복지 등 사회적 이슈
5. 자동화·정보 제공·예측·맞춤형 서비스 등 AI·디지털 기술로 해결 가능한 문제

F12는 이 가운데 **3번(지역사회) + 5번(AI·디지털)** 의 결합에 해당한다.

## 6. 중간간담회 발표 구성

운영진이 제시한 참고 항목:

1. 팀 소개
2. 프로젝트 소개 — 기획 배경, 문제와 필요성, 해결 방법
3. 역할 분담
4. 현재까지의 활동 — 조사, 인터뷰, 아이디어, 개발 등
5. 현재 고민 또는 어려운 점
6. 향후 계획 — 남은 활동, 추진 방향, 문제 해결 계획

**추가 원칙** — 팀 특성에 맞춰 자유롭게 구성한다. 다른 팀도 이해할 수 있도록 전문용어보다 쉽고 명확한 표현을 쓴다.

### 중심 서사

`신청 당시 약속 → 프로그램 시작 전 기준선 → SCC 기간 신규 활동 → 현장에서 배운 점 → 프로토타입 변화 → 현재 어려움 → 후반 검증계획`

### 우선 보여줄 증거

발표 항목 4번("현재까지의 활동")에 넣을 것을 우선순위대로 둔다.

1. 신청 주차계획 대비 완료·진행·지연 상태
2. SCC 이전 자산과 SCC 기간 신규 결과의 구분 (§7.5)
3. 안양 상권조사와 소상공인 인터뷰의 **실제 수량·기록**
4. 리뷰 데이터의 출처·기간·매장 수·리뷰 수
5. 실제 리뷰가 반복 의견·감정·쉬운 문장형 인사이트로 바뀌는 예
6. `리뷰 입력 → 인사이트 → 실행 제안` 작동 화면
7. 분석 오류 사례와 개선 내용
8. 멘토 피드백과 반영 이력
9. 후반부 영상·매칭·현장 사용성 테스트 일정

## 7. 외부 공유 규칙

### 7.1 수치 인용

**대외 자료(발표·보고서·포스터)에 쓰는 모든 수치는 [research/evidence_registry.csv](../../research/evidence_registry.csv) 의 근거 ID를 달 수 있어야 한다.** 레지스트리에 없거나 등급이 낮은 수치는 쓰지 않는다.

특히 다음은 **쓰지 않는다.**

- 80.3%를 "음식점 방문 리뷰 조사"라고 표현하지 않는다 (제품 전반 조사이고 2017년 자료다)
- 만안구 사업체 수가 적다는 사실만으로 상권 침체의 원인·결과를 확정하지 않는다
- 명학역 상권의 점포 수·폐업률·유동인구를 실제 추출 자료 없이 만들지 않는다
- AI 분석이 매출·재방문율을 높였다고 말하지 않는다
- 인터뷰 전에는 "사장님들이 원한다"가 아니라 **"검증할 가설"** 이라고 표현한다

근거별 상세 판정은 [PROBLEM_BASELINE.md](../product/PROBLEM_BASELINE.md) 를 따른다.

### 7.2 개인정보

- 발표·공유본에 전화번호, 이메일, 학번, 서명 이미지를 넣지 않는다
- 팀 소개에는 이름과 역할만 쓴다
- 인터뷰 대상과 매장 정보는 동의 범위에 맞춰 익명화한다
- 리뷰어 닉네임과 개인 식별정보는 제거한다
- Claude Code, ChatGPT, Perplexity, Veo 등 외부 AI 도구에 인터뷰 원문이나 연락처를 그대로 입력하지 않는다

### 7.3 실제 데이터와 예시 데이터

화면과 발표자료에서 **실제 수집 데이터와 시연용 예시 데이터를 명확히 구분해 표시한다.**

### 7.4 PULSE(졸업작품)와 SCC의 관계 ★

발표에서 반드시 질문받는 지점이다. **졸업작품을 SCC에 그대로 다시 낸 것 아니냐**는 오해를 막아야 한다.

**PULSE란** — SCC 이전부터 기획된 **외식업 사장님용 통합 마케팅 자동화 졸업작품**이다. 상권·손님 분석과 AI 코칭, 사진 기반 숏폼 영상 제작, 가게 현황 대시보드, 리뷰 답변 자동화, 구독·Pro 모델, 인플루언서 검색·협찬 요청 등 넓은 범위를 가진다.

- 기존 PULSE 기본 루프: `주변 상권·손님 분석 → 홍보영상 제작 → 가게 현황·다음 행동 → 다시 영상 제작`
- 기존 PULSE 별도 Pro 루프: `리뷰 관리·답변 + 인플루언서 협찬 매칭`

**SCC용 재정의** — SCC는 이 전체 제품을 다시 만드는 활동이 아니다.

| 축 | 기존 PULSE | SCC F12 |
|---|---|---|
| 성격 | 졸업작품·범용 마케팅 SaaS | 지역 문제해결·현장검증 프로젝트 |
| 사용자 | 외식업 사장님 일반 | **안양 만안구·명학역 인근 영세 외식업 소상공인** |
| 핵심 목적 | 반복 가능한 마케팅 자동화 | **디지털 격차 완화와 지역 현장 검증** |
| 기본 루프 | 분석 → 영상 → 가게 현황 | **분석 → 영상 → 인플루언서 확산** |
| 인플루언서 | 선택형 Pro·BM 기능 | **공식 신청서상 핵심 산출물** |
| 고유 성과 | 해당 없음 | **지역 데이터, 인터뷰, 사용성 테스트, 개선 과정** |
| 핵심 검증 질문 | — | 리뷰가 실제로 사장님의 손님 이해와 홍보 행동에 도움이 되는가 |

**발표에서 쓸 안전한 문장**

> PULSE는 졸업작품으로 기획된 전체 마케팅 플랫폼이며, SCC에서는 이를 완성품으로 다시 제출하는 것이 아니라 기존 PoC를 출발점으로 안양 지역 소상공인의 실제 문제에 적용하고 현장에서 검증·개선한다. 최종적으로는 신청서에 약속한 손님 분석·영상 제작·인플루언서 매칭을 단계적으로 연결하되, 중간시점에는 리뷰 인사이트와 실행 제안 흐름을 우선 검증한다.

### 7.5 기존 자산과 SCC 성과의 구분

2026-07-03 추가 제출자료에서 팀은 이미 "손님 분석 개발 완료"를 보고했다. 따라서 **손님 분석 자체를 SCC 기간의 신규 개발 성과로 표현하면 제출 문서와 충돌한다.**

| 구분 | 내용 |
|---|---|
| SCC 이전 기존 자산 | 손님 분석 기술·화면 PoC |
| SCC 기간 신규 활동 | 안양 데이터 적용, 실제 사장님 인터뷰, 결과 정확도 검증, 쉬운 문장·UX 개선 |
| SCC 기간 신규 구현 | 영상 제작, 인플루언서 매칭 등 기준선 이후의 기능 |
