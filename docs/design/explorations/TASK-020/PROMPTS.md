# TASK-020 ImageGen 프롬프트 원문

아래는 `codex exec`에 표준 입력으로 넘긴 **실제 입력 원문**이다. 생성 보드는 한 파일에 지시문·공통 조건·보드 조건이 모두 들어 있다. 공통 조건은 다섯 보드에 똑같이 들어가므로, B2~B5는 첫 두 문단(지시문·공통 조건)이 B1과 같고 보드 조건만 다르다. 지시문 둘째 문장의 첨부 이미지 안내는 첨부가 없는 B1·B2에도 들어갔지만 영향은 없다.

첨부 이미지: B3·B4·B5는 `docs/design/evidence/TASK-018/android-codex-fix-hero.png`를 `-i`로 첨부했다. 편집은 아래 표의 입력 이미지를 첨부했다. 첨부 여부는 실행한 명령 기준이며, `codex exec` 로그에는 첨부 인자가 남지 않는다.

> **프롬프트 지정 오류(2026-09-22 리뷰에서 발견):** SHARED와 B5는 주의 **막대**에 `#B45309`를 지정했다. DESIGN_SYSTEM §3.2·§3.3 기준으로 카드 위 비텍스트 주의 신호는 `status.warning` `#D97706`이고, `#B45309`는 주의 문장·아이콘용이다. 이미지는 이 지정에 따라 그려졌으므로 막대 색을 합성 근거로 쓰지 않는다.

````text
이미지 생성 도구로 아래 조건의 이미지 1장을 생성해줘. 파일 편집·셸 명령·다른 작업은 하지 말고, 생성이 끝나면 한 줄로 완료만 알려줘. 첨부 이미지가 있으면 홈 결과 화면의 시각 언어(네이비 히어로, 흰 카드, 음식 일러스트 포디움) 참고용이며 그 안의 개발용 표시(Tools 버튼, 경고 토스트, 실행 프로토타입 배지)는 따라 그리지 마.

한국 음식점 사장님용 Android 앱 "PULSE"의 모바일 UX 탐색 보드를 그려줘. 결과물은 실제 제품이 아니라 서로 다른 UX 가설을 비교하는 탐색 이미지다.

형식

## B1 — 한 화면 이어쓰기형 (정보 밀도·맥락 유지)

보드 제목: "가설 1 · 한 화면 이어쓰기 — 입력한 내용을 보면서 기다린다"
화면 ① "가게 정보 입력" (하단 내비게이션 없음): 상단에 "PULSE" 로고 텍스트와 "첫 분석"이라는 작은 표시. 제목 "우리 가게 리뷰를 분석해요". 라벨이 보이는 입력칸 3개가 한 카드 안에 세로로: "가게 이름" 값 "영등원조쌈밥" / "업종" 가로 칩 목록 "한식 중식 일식 양식 카페/디저트 주점 기타" 중 "한식" 선택(네이비) / "네이버 가게 URL" 값 "naver.me/예시". 카드 아래 오렌지 버튼 하나 "분석하기".
화면 ② "진행 중" (하단 내비게이션 없음): 같은 화면이 이어진다. 입력 카드는 한 줄 요약 카드로 접힘 "영등원조쌈밥 · 한식 · naver.me/예시"와 옆의 작은 텍스트 버튼 "입력 보기". 그 아래 세로 타임라인: 체크 표시 "분석 준비 완료", 진행 중 표시 "네이버 리뷰 수집 중"(굵게, 작은 원형 로딩 표시). 그 아래 회색 안내문 "서버가 알려준 단계만 보여줘요. 다음 단계가 오면 여기에 추가돼요." 앞으로의 단계를 미리 나열하지 않는다. 퍼센트 막대 없음.
화면 ③ "가게를 찾지 못했을 때" (하단 내비게이션 없음): 화면 ①과 같은 입력 카드가 다시 펼쳐져 있고 값이 그대로 남아 있다. "네이버 가게 URL" 입력칸 테두리가 붉은색이고 바로 아래 오류 문장 "! 가게를 찾지 못했어요. 가게 이름과 URL을 확인해 주세요." 카드 위에 흰 안내 띠 "입력한 내용은 그대로 두었어요." 오렌지 버튼 "다시 분석하기".
````
