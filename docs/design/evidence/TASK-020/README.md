## 선택 유형 요약 카드 (2026-09-28)

사용자가 대화 안 시안 6개 가운데 F안(관점별 근거 수 칩)을 고르고, 왼쪽 그림은 음식 대신 손님 캐릭터로 해 달라고 했다. 결과 화면의 큰 이미지 칸을 이 카드로 바꿨다(사용자 선택). 같은 AVD·Expo Go, 가상 서버 모드.

| 파일 | 확인한 것 |
|---|---|
| `stats-card-01-rank1.png` | 1위 — 안경 손님, `1위 손님`, `리뷰 24건`, 막대, `분석한 리뷰 67건 중 36%`, 칩 4개(먼저 볼 것 12·잘하고 있는 점 18·손님이 불편해한 점 11·손님이 기억하는 모습 9) |
| `stats-card-02-rank2.png` | 시상대에서 2위를 누른 뒤 — 올림머리 손님, 19건, 28%, 칩 10·15·8·7 |
| `stats-card-03-image-error.png` | 가상 서버 상황 `이미지 조회 실패`로 다시 분석한 결과 — 그림은 캐릭터, 카드 안에 `이미지를 불러오지 못했어요. 손님 유형 내용은 그대로 볼 수 있어요.`, 다시 불러오기 버튼은 없음(가상 서버에는 다시 받을 이미지가 없다) |

- 비율은 앱 계산값이다(24÷67=35.8→36, 19÷67=28.4→28). 한 리뷰가 여러 유형에 세어지는지는 계약에 없어 SCREEN_STATES §11에 올렸다.
- 처음 반영 때 Fast Refresh가 편집 중간 상태(`fontFamilies` import 전)를 불러와 오류 화면이 떴다. `typecheck`는 import 뒤 통과했고, Metro `/reload` 뒤 정상으로 떴다. 캡처는 모두 다시 불러온 뒤의 것이다.
- 독립 리뷰 1차 FAIL(P1 — 카드가 그림을 묶으면서 서버 대체 텍스트가 읽히지 않음)을 고친 뒤, `uiautomator dump`의 카드 접근성 이름이 `추억 재방문형을 나타내는 따뜻한 음식 그릇과 재방문 모티프. 1위 손님, 리뷰 24건, 분석한 …`으로 시작하는 것을 확인했다. TalkBack으로 실제 읽어 본 것은 아니다.
- 미확인: 실제 원격 이미지의 로딩 회색 원과 `이미지 다시 불러오기` 동작(가상 서버에 원격 이미지 없음), 3위 선택, 글자 크기 200%, TalkBack, 실기기.

### 고친 결함

- (독립 리뷰 반영) **현재 화면 탭을 누르면 "아직 연결하지 않은 화면"이라는 틀린 안내가 떴다.** 활성 탭은 눌러도 아무 일도 하지 않게 했고 눌림 표현도 빼서 현재 화면임을 유지한다(`components/ui/BottomNavigation.tsx`).
- (독립 리뷰 반영) **가게 입력을 바꾸고 다시 보내도 직전 `Idempotency-Key`를 다시 썼다.** 같은 키로 보낸 입력을 기억해, 입력이 다르면 새 키를 만든다(공통 불변식 13).
- (독립 리뷰 반영) **작업 상태 조회가 겹쳐 실행될 수 있었다.** 응답이 주기(1.2초)보다 느리면 요청이 쌓여 완료 처리가 두 번 일어난다 → 진행 중 플래그로 막았다.
- (독립 리뷰 반영) **약관이 바뀌어 다시 동의를 받을 때 그 사실을 알리는 안내가 곧바로 지워졌다** → 다시 조회할 때 이 안내만 남긴다(`AUTH-CONSENT-OUTDATED`).
- (독립 리뷰 반영) **`setHasSavedAnalysis`의 identity가 매 렌더 바뀌어** 홈 화면 조회 이펙트가 다시 돌 수 있었다 → `useCallback`으로 고정하고 값이 같으면 상태를 바꾸지 않는다.
- (독립 리뷰 반영) 페르소나 순위 목록이 응답 배열 순서를 그대로 썼다. 계약에 rank 정렬 보장이 없다 → rank로 정렬한 뒤 그리고, 최초 선택도 가장 낮은 rank로 한다.
- (독립 리뷰 반영) 제안이 0건이면 `검토해 볼 행동` 영역이 통째로 사라져 왜 없는지 알 수 없었다(`ADVICE-EMPTY`) → 제목을 남기고 이유를 적는다.
- (독립 리뷰 반영) 하단 고정 영역이 `SafeArea` 밖이라 가로 화면에서 컷아웃에 닿을 수 있었다 → `Screen`이 footer의 좌우도 감싼다.
- (독립 리뷰 반영) 탭 이동이 `push`라 뒤로가기 스택이 쌓였다 → 세 탭 모두 `navigate`로 맞췄다. 스택에 이미 있는 화면이면 그리로 돌아가고 없으면 쌓는다.
- (독립 리뷰 반영) 확인 대화상자의 배경 `Pressable`이 접근성 초점을 가져가 안쪽 제목·버튼이 개별 초점을 받지 못했다 → 배경과 본문 래퍼를 초점에서 뺐다(`accessible={false}`). 초점을 받지 않는 노드에 `accessibilityRole="alert"`를 두면 읽히지 않으므로 함께 지웠다. 제목의 `accessibilityRole="header"`는 그대로 둔다. TalkBack으로 초점 순서를 확인하지는 못했다.
- (독립 리뷰 반영) 쓰지 않는 export 2개(`resetFixtureServer`, `secureStorageAvailable`)와, 구현하지 않은 동작을 설명하는 주석을 지웠다.

### 2차 독립 리뷰에서 다시 찾은 것 (같은 단계 안에서 고침)

- **P2 — 대화상자 본문을 누르면 닫혔다.** 접근성 수정으로 본문 래퍼를 `Pressable`에서 `View`로 바꿨는데, 터치 핸들러가 없는 `View`는 RN 반응자 협상에서 responder가 되지 않아 배경의 `onPress={onDismiss}`가 그대로 발화했다. 저장 교체·로그아웃처럼 되돌릴 수 없는 확인에서 문구를 읽으려고 누르기만 해도 닫히는 상태였다 → 본문을 `Pressable accessible={false} onPress={() => undefined}`로 되돌려 터치를 삼키게 하고, 초점은 여전히 갖지 않게 했다. Android에서 본문 탭·배경 탭을 모두 확인했다(`step10-05`).
- **P2 — 탭 이동을 `replace`로 바꾼 탓에 뒤로 갈 곳이 없었다.** 진입이 `Redirect`(=replace)라 스택 깊이가 1인데 탭 이동까지 `replace`면 `/analyze`·`/mypage`에서 하드웨어 뒤로가기에 pop 대상이 없다. 이 화면들에는 뒤로 버튼도 `BackHandler`도 없어 앱이 종료된다 → `navigate`로 바꿨다. Android에서 두 화면 모두 뒤로가기로 홈에 돌아오는 것을 확인했다(`step10-03`·`step10-04`).
- (3차 리뷰에서 되돌림) 좌우 SafeArea 띠에 배경색을 주려고 래퍼에 `background.surface`를 줬는데, 좌우 inset이 0인 세로 모드에서는 래퍼 rect가 footer와 같아져 저장 선택 바의 `radii.panel`(24) 둥근 모서리 뒤가 흰색으로 채워졌다 → 래퍼 배경을 다시 뺐다. 좌우 띠에 화면 배경이 보이는 문제는 컷아웃 기기가 없어 재현·판단하지 못했고, 미확인으로 남긴다.
- 약관 재동의 때 비밀번호를 지우면서 그 사실을 알리지 않았다 → 안내 문구에 덧붙였다.
- `Screen.tsx`의 주석이 "좌우·아래를 SafeArea로 감싼다"였으나 실제로는 좌우만 감싼다(아래는 각 footer가 `bottomInset`으로 처리) → 주석을 사실에 맞췄다.

2차 리뷰의 나머지 지적 중 **성립하지 않은 것**: 순위 목록의 빈 슬롯도 누를 수 있다는 지적. `PodiumSlot.status`는 `'FILLED' | 'EMPTY'` 두 값뿐이고, 순위 목록이 `status === 'EMPTY' || !persona`를 눌리지 않는 `View`로 반환한다(그때는 `PodiumCard`, 2026-09-27부터는 `PodiumTop3`). 이는 `filled` 조건(`status === 'FILLED' && persona`)의 정확한 보수라 누를 수 있는 빈 슬롯은 생기지 않는다.

### 4차 리뷰에서 고친 것 (문서만)

4차 리뷰는 **코드에서 결함을 찾지 못했다**(P1 0·P2 0). 지적은 전부 "문서가 코드와 어긋난다"였다.

- handoff가 `Screen.tsx`를 "footer 좌우 SafeArea와 배경색"이라고 적었으나 배경색은 3차에서 지웠다 → 주지 않는다는 사실과 이유로 고쳤다.
- handoff가 캡처를 5장이라고 적었으나 실제 7장이다 → 고쳤다.
- `FRONTEND_STRUCTURE.md`가 치수 리터럴 2건을 "DESIGN_SYSTEM §13 미결 항목과 함께 기록"이라고 적었으나 §13에 그 기록이 없다 → 참조를 지우고 이 표가 유일한 기록임을 밝혔다. `DESIGN_SYSTEM.md`는 `role:design-system` 소유라 행을 추가하지 않았다.
- 미확인 항목에 같은 사실이 두 줄로 있었다 → 한 줄로 합쳤다.

### 문서에서 고친 것

- `SCREEN_STATES.md` §13 8차 기록에서 `AUTH-SIGNUP-UNAVAILABLE`을 "코드와 fixture 경로는 있다"고 적었으나 **경로가 없다.** 구현하지 않았다고 바로잡았다. `AUTH-CONSENT-OUTDATED`도 UI 조작으로는 재현할 수 없다는 사실을 적었다.
- `FRONTEND_STRUCTURE.md`에서 8단계 때 `9단계`라고 적어 둔 항목 중 9단계에서 하지 않은 4건을 `미이행`으로 바로잡았다. 치수 리터럴 개수도 `ProgressList`의 모듈 상수를 빠뜨려 1건으로 셌던 것을 2건으로 고쳤다.

### 미확인

- 화면으로 확인한 것은 탭 가드 2건, 뒤로가기 2건, 대화상자 본문·배경 탭 2종, 저장 선택 바의 둥근 모서리다. 나머지(멱등 키, polling 중복, 순위 정렬, `setHasSavedAnalysis`)는 코드 확인과 회귀 실행으로만 판정했다
- `ADVICE-EMPTY`: 가상 서버에 제안 0건 상황이 없어 화면으로 보지 못했다
- 컷아웃 기기 가로 모드의 하단 고정 영역: 좌우 SafeArea 띠에 화면 배경이 드러나는지 확인하지 못했다. 재현할 기기가 없다
- 실제 백엔드 연결·TalkBack·실기기: 미실행

- `이미지 다시 불러오기` 버튼의 실제 재조회 동작: 미확인. 가상 서버에는 내려받을 이미지가 없어 이 버튼은 실제 서버 모드에서만 나온다
