# SCC — Design System

**이 문서는 SCC 손님분석 MVP의 UI/UX 원칙과 구현 전 디자인 기준의 정본이다.**

실제 디자인 토큰과 컴포넌트가 생기면 값과 동작의 정본은 코드가 된다. 이 문서는 코드가 지켜야 할 의미·우선순위·사용 규칙과, 코드 생성 전 이식할 기준값을 관리한다.

|---|---|
| 상태 | **PULSE 디자인 기준 반영 / 구현 전 초안** |
| 최종 수정 | 2026-09-11 |
| 소유 역할 | `role:design-system` |

## 1. 적용 범위와 우선순위

이 디자인 시스템은 다음 사용자 흐름에 적용한다.

```text
가게 지정
→ 리뷰 수집·분석 진행
→ 긍정·부정·인식·우선순위 확인
→ 손님 유형과 페르소나 확인
→ 리뷰 근거가 연결된 운영·마케팅 제안 확인
```

현재 MVP에 없는 로그인, 회원가입, 대시보드, 리뷰 답글 관리, 홍보영상, 인플루언서, 요금제 화면은 적용 범위가 아니다. 해당 기능이 PRD에 추가되기 전에는 이 문서에 화면 규칙을 만들지 않는다.

정보가 충돌하면 영역별 정본을 따른다.

| 정보 | 정본 |
|---|---|
| 제품 기능과 범위 | `docs/product/PRD.md` |
| 화면·기능·상태 | `docs/product/requirements/GUEST_ANALYSIS_FUNCTIONAL_SPEC.md` |
| 디자인 의미와 사용 원칙 | 이 문서 |
| 실제 색상·간격·타입 값 | 구현 후 토큰 코드 |
| 컴포넌트 props와 동작 | 구현 후 컴포넌트 코드와 타입 |

## 2. 디자인 방향

### 2.1 철학

PULSE에서 사용한 `Modern Professional & Universal Clarity`를 SCC의 기본 방향으로 이어받는다.

- **Professional** — 분석 결과를 장식보다 근거와 구조로 신뢰하게 한다.
- **Clear** — 분석 용어 대신 외식업 점주가 바로 이해하는 문장을 쓴다.
- **Focused** — 한 화면에는 하나의 핵심 행동 또는 하나의 판단 단위를 둔다.
- **Evidence-first** — 화려한 페르소나보다 실제 리뷰 근거를 먼저 확인할 수 있게 한다.
- **Mobile-first** — 작은 화면에서도 가게 지정부터 결과 확인까지 막힘없이 완료하게 한다.

### 2.2 시각적 성격

- 딥 로얄 블루와 화이트를 신뢰·분석의 기본 인상으로 사용한다.
- 오렌지는 분석 시작, 재시도, 제안 확인 등 사용자의 명확한 행동에 제한해 사용한다.
- 넓은 여백, 명확한 제목 계층, 둥근 카드로 복잡한 분석 결과를 짧은 판단 단위로 나눈다.
- 상태색은 의미 전달에 사용하되 색상만으로 긍정·부정·오류를 표현하지 않는다.
- AI 생성 이미지는 정보보다 앞에 나오지 않으며 실제 고객 사진처럼 보이게 사용하지 않는다.

## 3. 토큰 정본과 이식 기준

### 3.1 토큰 정본 위치

현재 코드가 없어 토큰 파일 위치와 표현 방식은 미정이다.

| 항목 | 상태 |
|---|---|
| 토큰 표현 방식 | 기술 스택 확정 후 결정 |
| 토큰 파일 경로 | 기술 스택 확정 후 결정 |
| 공용 컴포넌트 경로 | 기술 스택 확정 후 결정 |

스택 확정 후 ADR을 작성하고 이 표를 실제 경로로 교체한다. CSS variables, Tailwind theme, theme object 중 선택한 프레임워크의 관례를 우선한다.

### 3.2 색상 이식 기준

아래 값은 사용자 제공 PULSE 대조본에서 확인된 기존 코드 값이다. SCC 토큰 코드를 만들 때의 **초기 이식 기준**이며, 아직 이 저장소에서 실행 검증된 값은 아니다.

| 의미 토큰 후보 | 값 | 용도 |
|---|---|---|
| `primary` | `#002B7A` | 브랜드, 주요 정보, 선택 상태 |
| `primary-hover` | `#002B7AE6` | 주요 버튼 hover 후보 |
| `primary-sub` | `#002B7ACC` | 보조 강조 |
| `primary-inactive` | `#002B7A99` | 비활성 강조 후보 |
| `primary-border` | `#002B7A66` | 강조 경계선 |
| `primary-tint` | `#002B7A1A` | 선택·정보 배경 |
| `primary-stripe` | `#002B7A0D` | 아주 연한 구분 배경 |
| `action` | `#FF5A36CC` | 분석 시작·재시도 등 행동 CTA |
| `action-bg` | `#FF5A361A` | 행동 관련 연한 배경 |
| `action-hover` | `#FF5A3633` | 기존 코드의 action hover 후보 |

| `neutral-900` | `#0F172A` | 강한 제목 |
| `success` | `#059669` | 성공 |

8자리 HEX 색상은 알파값을 포함한다. 실제 배경에 합성됐을 때 대비가 달라지므로, `action`, `primary-sub`, `neutral-400` 등을 텍스트나 버튼에 사용할 때는 구현 화면에서 WCAG 대비를 검증한다. 검증 전에는 “접근성 충족”으로 판정하지 않는다.

### 3.3 색상 사용 규칙

- `primary`는 브랜드와 분석 정보의 기본색이다.
- `action`은 사용자가 실행하는 핵심 CTA에만 사용한다. 화면마다 오렌지 CTA를 여러 개 경쟁시키지 않는다.
- 긍정·부정 신호에 success/error 색상을 사용할 수 있지만 반드시 아이콘·레이블·문장을 함께 둔다.
- “리뷰에서 확인된 것”과 “AI 해석”은 색만 바꾸지 말고 제목, 배지, 카드 구조로 구분한다.
- 경고색은 리뷰 부족, 데이터 편향, 결과 한계처럼 사용자의 판단에 필요한 주의에 사용한다.
- 기능마다 새로운 임시 브랜드색을 추가하지 않는다. 필요한 경우 `role:design-system` 검토 후 토큰으로 추가한다.
- 컴포넌트 안에 HEX, RGB, HSL 값을 직접 적지 않는다.

### 3.4 타이포그래피 이식 기준

기본 글꼴은 PULSE에서 사용한 Pretendard 계열을 우선한다.

```text
"Pretendard Variable", Pretendard, -apple-system,
BlinkMacSystemFont, system-ui, Roboto, sans-serif
```

기존 PULSE 코드에서 확인된 타입 스케일을 초기 이식 기준으로 사용한다.

| 토큰 후보 | 크기 | 굵기 | 행간 후보 | 주 사용처 |
|---|---:|---:|---:|---|
| `head-1` | 34px | 700 | 1.4 | 결과 페이지 제목 |
| `head-2` | 32px | 600 | 1.4 | 주요 섹션 제목 |
| `head-3` | 26px | 600 | 1.4 | 결과 그룹 제목 |
| `head-4` | 22px | 600 | 1.4 | 카드 묶음 제목 |
| `head-5` | 20px | 600 | 1.4 | 카드 제목 |
| `body-1` | 18px | 700 | 확정 필요 | 강한 본문·핵심 수치 |
| `body-2` | 18px | 500 | 확정 필요 | 강조 본문 |
| `body-3` | 18px | 400 | 확정 필요 | 넓은 화면 본문 후보 |
| `body-4` | 16px | 400 | 확정 필요 | 기본 본문 |
| `body-5` | 14px | 700 | 확정 필요 | 작은 강조문 |
| `body-6` | 14px | 600 | 확정 필요 | 레이블 |
| `body-7` | 14px | 400 | 확정 필요 | 보조 정보 |
| `caption` | 12px | 400 | 확정 필요 | 날짜·출처·메타데이터 |
| `button-main` | 16px | 600 | 확정 필요 | 주요 버튼 |
| `button-sub` | 15px | 500 | 확정 필요 | 보조 버튼 |
| `error-text` | 13px | 500 | 확정 필요 | 입력 오류 |

모든 타입 토큰의 자간 후보는 기존 값인 `-0.02em`이다. 모바일에서 `head-1`이 과도하면 반응형 타입 토큰을 별도로 정의한다. 본문은 기본 16px를 우선하고, 12~14px 텍스트는 부가 정보에만 사용한다.

### 3.5 간격·모서리·그림자 기준

기존 PULSE 문서의 계층 기준을 SCC의 시작점으로 사용한다.

| 대상 | 기준 후보 |
|---|---|
| 페이지 좌우 여백 | 모바일 16px 이상, 실제 breakpoint별 값은 토큰으로 확정 |
| 메인 결과 패널 | radius 24px |
| 내부 카드·버튼 | radius 12px |
| 배지·작은 요소 | radius 8px 또는 pill |
| 부드러운 강조 그림자 | `0 4px 20px rgba(0, 43, 122, 0.15)` 후보 |

- spacing, radius, shadow는 토큰으로 정의한다.
- 분석 카드마다 서로 다른 모서리값을 임의로 추가하지 않는다.
- 그림자로만 카드 경계를 표현하지 않는다. 저대비 환경을 위해 배경이나 경계선도 고려한다.
- 기존 PULSE에서 관찰된 28px, 30px, 32px 예외값은 SCC의 전역 토큰으로 자동 승격하지 않는다.

## 4. 정보 구조와 결과 표현

### 4.1 결과의 읽는 순서

사용자가 결과를 다음 순서로 이해하게 한다.

1. 어떤 리뷰를 언제 얼마나 분석했는가
2. 가장 먼저 볼 긍정·부정·인식·우선순위는 무엇인가
3. 그 판단을 뒷받침하는 리뷰는 무엇인가
4. 어떤 손님 사용 상황이 반복되는가
5. AI는 무엇을 해석했는가
6. 어떤 행동을 검토할 수 있는가

페르소나 이미지가 근거 리뷰나 핵심 우선순위보다 먼저 시선을 독점하지 않게 한다.

### 4.2 사실과 해석의 구분

| 레이어 | 표시 원칙 |
|---|---|
| 리뷰에서 확인된 것 | `리뷰에서 확인` 레이블, 근거 리뷰 진입점, 수집 메타데이터 제공 |
| AI 해석 | `AI 해석` 레이블과 추론임을 알리는 문장 제공 |
| 전문 지식 참고 | 자료명 또는 출처를 확인할 수 있는 진입점 제공 |
| 제안 | 명령이나 보장이 아니라 `검토해 볼 행동`으로 표현 |

레이어는 배경색만 달리하지 않는다. 카드 제목, 배지, 아이콘, 설명 순서를 함께 사용한다.

### 4.3 긍정·부정·우선순위

- 긍정 신호는 “잘하고 있는 점”, 부정 신호는 “손님이 불편해한 점”처럼 쉬운 문장으로 표현한다.
- 부정 신호를 공격적이거나 심판하는 어조로 표현하지 않는다.
- 우선순위는 중요도 숫자만 제시하지 말고 왜 먼저 볼 항목인지 설명한다.
- 수치와 비율은 분석 리뷰 안에서의 관찰값임을 표시한다.
- 리뷰가 부족하면 완성된 결과 카드 대신 한계와 다음 행동을 보여준다.

### 4.4 페르소나

- 페르소나는 실제 인물이 아니라 리뷰 패턴을 설명하는 가상 표현이다.
- 인구통계가 확인되지 않았다면 나이·성별·직업을 단정하지 않는다.
- AI 생성 이미지에는 생성 사실을 텍스트로 고지한다.
- 이미지를 숨겨도 유형명·특징·근거 리뷰를 이해할 수 있어야 한다.
- 대체 텍스트는 외모를 과도하게 묘사하지 않고 이미지의 기능을 설명한다.

## 5. 컴포넌트 원칙

### 5.1 중복 금지

새 컴포넌트를 만들기 전에 기존 컴포넌트를 최소 두 가지 이름으로 검색한다.

- `Modal` / `Dialog`
- `Input` / `TextField`
- `Card` / `Panel`
- `Progress` / `Stepper`
- `Alert` / `Notice`

기존 것을 props로 확장할 수 있으면 확장한다. 새 공용 컴포넌트나 토큰은 `role:design-system` 리뷰 대상이다.

### 5.2 필수 상태

인터랙티브 컴포넌트는 다음 상태를 정의한다.

```text
default / hover / focus / active / disabled / loading / error
```

데이터 컴포넌트와 화면은 다음 상태를 정의한다.

```text
loading / empty / error / normal / partial-success
```

`partial-success`는 텍스트 분석은 성공했지만 페르소나 이미지 같은 P1 기능만 실패한 상태에 사용한다.

### 5.3 MVP 컴포넌트 목록

경로와 props는 구현 후 채운다.

| 컴포넌트 | 책임 | 경로 |
|---|---|---|
| StoreInput | 가게명 또는 지도 URL 입력과 검증 안내 | TBD |
| StoreCandidateList | 같은 이름의 가게 후보 선택 | TBD |
| AnalysisProgress | 수집·분석 단계와 현재 상태 표시 | TBD |

| EvidenceReviewList | 작성자 정보 없는 근거 리뷰 표시 | TBD |

| PersonaCard | 손님 유형, 관찰 특성, 근거와 한계 표시 | TBD |

### 5.4 버튼

- 한 화면의 주요 CTA는 원칙적으로 하나다.
- 주요 분석 행동에는 action 색상을 사용할 수 있다.
- 정보 탐색·근거 확인에는 primary 또는 ghost 계열을 사용한다.
- disabled와 loading을 시각적으로 구분하고 둘 다 실제 클릭을 막는다.
- 로딩 중 버튼의 텍스트를 단순히 숨기지 말고 수행 중인 행동을 알린다.
- 포커스 링을 제거하지 않는다.

### 5.5 입력

- 가게명과 지도 URL을 하나의 입력에서 받을지, 탭으로 분리할지는 UX 시안에서 결정한다.
- 입력에는 시각적 label을 연결한다. placeholder를 label 대신 쓰지 않는다.
- 오류가 있으면 원인과 수정 방법을 입력 가까이에 표시한다.
- URL 형식이 맞아도 허용 도메인이 아니면 수집을 시작하지 않는다.
- 입력 중 검증과 서버 검증 결과를 구분한다.

### 5.6 카드와 배지

- 카드 하나는 하나의 판단 단위를 담는다.
- 결과 카드에는 제목, 요약, 근거 진입점, 필요 시 한계를 같은 순서로 둔다.
- 배지는 짧은 상태나 분류에만 사용한다. 긴 설명을 배지 안에 넣지 않는다.
- AI 관련 배지는 장식이 아니라 생성·해석 주체를 알리는 용도로 사용한다.

## 6. 기능명세 화면별 적용

| 화면 | 디자인 적용 기준 |
|---|---|
| SC-001 시작·가게 지정 | 한 개의 핵심 입력과 한 개의 분석 CTA. 서비스 설명은 입력을 밀어내지 않게 한다 |
| SC-002 가게 확인 | 가게명·주소·플랫폼을 짧게 확인. 후보가 여러 개일 때 선택 상태를 명확히 표시 |
| SC-003 분석 진행 | 현재 단계, 진행 중임, 화면을 닫아도 되는지 여부를 문장으로 표시. 확정되지 않은 퍼센트는 만들지 않는다 |
| SC-004 결과 요약 | 4개 관점을 동일한 정보 계층으로 제공하되 우선순위를 먼저 인지할 수 있게 한다 |
| SC-005 근거 상세 | 닉네임·프로필 없이 리뷰 본문과 필요한 메타데이터만 제공 |
| SC-006 손님 유형 | 이미지보다 유형명·관찰 특성·근거·한계가 우선 |
| SC-007 페르소나 이미지 | AI 생성 고지, 대체 텍스트, 실패 대체 상태 제공 |
| SC-008 실행 제안 | 사실→해석→지식→제안 흐름을 세로로 읽을 수 있게 구성 |
| SC-009 오류·한계 | 원인, 현재 상태, 사용자가 할 수 있는 다음 행동을 함께 제공 |

## 7. 반응형

- 모바일을 기본 레이아웃으로 설계하고 넓은 화면에서만 열 수를 늘린다.
- 페이지 전체에 가로 스크롤이 생기지 않게 한다.
- 근거 리뷰와 제안은 좁은 화면에서 세로 순서로 제공한다.
- 데스크톱 2열 레이아웃을 모바일에서 비율 축소하지 않고 1열로 재배치한다.
- 고정 너비 사이드바나 480px 보조 패널을 MVP 기본 구조로 가져오지 않는다.
- `100vh`에 모든 결과를 강제로 넣지 않는다. 긴 분석 결과는 자연스러운 페이지 스크롤을 허용한다.
- 넓은 표가 필요한 경우 표 영역만 스크롤시키되, 모바일에서는 카드형 대안을 우선 검토한다.
- 기준 breakpoint는 토큰으로 정의하고 컴포넌트마다 임의의 값을 추가하지 않는다.

사용자 제공 대조본에서 기존 PULSE Dashboard가 1280px, 1024px 및 390px에서 일부 잘린 사실이 기록됐다. SCC는 그 레이아웃을 재사용 완료 상태로 간주하지 않으며, 실제 지원 너비에서 별도 검증한다.

## 8. 접근성

### 8.1 최소 기준

- 키보드만으로 가게 지정부터 결과 확인까지 완료할 수 있어야 한다.
- 포커스 표시를 제거하지 않는다.
- 폼 입력에 프로그램적으로 연결된 label을 제공한다.
- 이미지·아이콘 버튼에 대체 텍스트 또는 접근 가능한 이름을 제공한다.
- 색상 외에 텍스트·아이콘·형태로 상태를 구분한다.
- 진행 상태와 오류는 보조기술이 인식할 수 있는 상태 메시지로 제공한다.
- 글자 크기 확대 시 기능과 내용이 잘리지 않아야 한다.
- 모션 감소 설정을 존중한다.

### 8.2 정량 기준

WCAG 목표 등급과 지원 브라우저·보조기술 조합은 확정 필요다. 확정 전에도 일반 텍스트와 컨트롤의 대비, 키보드 흐름, 포커스, 200% 확대를 검증한다.

---

## 9. 모션

기존 PULSE에서 Button 0.15초, Modal 0.2초, Drawer 0.25초, 일반 fade-in 0.3초가 사용됐다. SCC 구현 시 참고할 수 있지만 자동 확정값은 아니다.

- 모션은 상태 변화와 화면 관계를 설명할 때만 사용한다.
- 분석 결과가 실제보다 빠르거나 확정적인 것처럼 보이게 하는 가짜 진행 애니메이션을 사용하지 않는다.
- 반복되는 장식 모션을 피한다.
- `prefers-reduced-motion`에서 비필수 모션을 제거한다.
- 로딩 스피너만 보여주지 말고 현재 처리 단계를 문장으로 함께 표시한다.

## 10. 카피

- “토픽 군집화”, “임베딩”, “RAG” 대신 사용자가 이해하는 결과 중심 표현을 쓴다.
- “고객의 실제 모습” 대신 “리뷰에서 반복된 손님 사용 상황”이라고 쓴다.
- “매출이 오릅니다” 대신 “검토해 볼 운영·홍보 행동”이라고 쓴다.
- “분석 실패”만 표시하지 않고 무엇이 실패했고 다시 시도할 수 있는지 설명한다.
- 리뷰 부족과 데이터 편향을 숨기지 않는다.
- CTA는 `분석하기`, `근거 리뷰 보기`, `다시 시도`처럼 행동이 분명한 동사를 쓴다.

## 11. 반영하지 않은 기존 PULSE 요소

사용자 제공 자료에 존재하지만 현재 SCC MVP 범위 밖이므로 이식하지 않은 항목이다.

- 로그인·회원가입의 2분할 3D 화면
- 고정 Sidebar와 Dashboard 셸
- 리뷰 답글 관리 탭과 템플릿
- 홍보영상 생성 화면
- 인플루언서 탐색·제안·인박스
- 마이페이지와 요금제
- 성과 그래프와 결제·크레딧 UI
- 기존 화면에만 사용된 보라색 AI 버튼

이 요소가 필요해지면 PRD 범위를 먼저 변경하고, 실제 자산·코드 사용 권한과 현재 구현 상태를 확인한 뒤 이식한다.

## 12. 검증

UI 변경은 `.claude/skills/visual-qa/SKILL.md` 절차를 읽고 실제 렌더링으로 검증한다.

최소 검증 대상:

| 범주 | 확인 내용 |
|---|---|
| 토큰 | 코드에 정의된 값과 이 문서의 의미가 일치하는가 |
| 컴포넌트 | 필수 인터랙션·데이터 상태가 모두 구현됐는가 |
| 모바일 | 지원 최소 너비에서 페이지 가로 스크롤·잘림이 없는가 |
| 접근성 | 키보드, 포커스, label, 대체 텍스트, 상태 알림, 대비 |
| 내용 | 사실·AI 해석·지식·제안이 시각적·언어적으로 구분되는가 |
| 근거 | 모든 표시 결과에서 연결된 근거 리뷰에 접근할 수 있는가 |
| 실패 | 리뷰 부족, 수집 오류, 모델 오류, 이미지 부분 실패가 구분되는가 |

실행하지 않은 검증은 `미실행`, 확인하지 못한 상태는 `미확인`으로 기록한다.
