# SCC — Design System

**이 문서는 UI/UX 원칙의 정본이다.**

**실제 디자인 값(색상 hex, 간격 px, 폰트 크기)의 정본은 이 문서가 아니라 토큰 코드다.**
Code-first 방식이므로 Markdown과 코드가 다르면 **코드가 실제 값의 정본**이고, 이 문서는 그 코드가 지켜야 할 원칙을 정한다.

## 1. 토큰 정본 위치

**미정.** 스택이 확정되지 않아 토큰을 어떤 형태로 둘지 정해지지 않았다.

확정 시 결정할 것:

| 항목 | 상태 |
|---|---|
| 토큰 표현 방식 (CSS variables / Tailwind theme / theme object / 별도 패키지) | 확정 필요 |
| 토큰 파일 경로 | 확정 필요 |
| 공용 컴포넌트 경로 | 확정 필요 |

결정하면 `docs/decisions/` 에 ADR을 남기고 이 표를 실제 경로로 교체한다.
**기존 프레임워크의 관례가 있으면 그것을 따른다.** 구조를 맞추려고 기존 토큰 시스템을 다시 쓰지 않는다.

## 2. 토큰 범주

값이 정해지면 아래 범주로 정의한다. **여기에 값을 적지 않는다. 코드에 정의하고 여기에는 범주만 둔다.**

| 범주 | 용도 |
|---|---|
| color | 배경/전경/강조/상태(성공·경고·오류)/경계선 |
| typography | 폰트 패밀리, 크기 스케일, 굵기, 행간 |
| spacing | 간격 스케일 (한 축으로 통일) |
| radius | 모서리 반경 |
| shadow | 고도 표현 |
| breakpoint | 반응형 중단점 |
| z-index | 레이어 순서 |

## 3. 원칙

### 3.1 토큰 우회 금지

색상·간격·타이포는 **항상 토큰을 통해** 쓴다. 컴포넌트 안에 값을 직접 적지 않는다.
토큰에 없는 값이 필요하면 하드코딩하지 말고 토큰 추가를 `role:design-system` 에 제안한다.

### 3.2 컴포넌트 중복 금지

새 컴포넌트를 만들기 전에 반드시 기존 컴포넌트를 **최소 2가지 이름으로** 검색한다.
(예: `Modal`/`Dialog`, `Input`/`TextField`, `Card`/`Panel`)
기존 것을 props로 확장할 수 있으면 확장한다.

### 3.3 상태를 빠뜨리지 않는다

인터랙티브 요소는 다음 상태를 모두 정의한다.

```
default / hover / focus / active / disabled / loading / error
```

데이터를 표시하는 화면은 다음을 모두 정의한다.

```
loading / empty / error / 정상
```

### 3.4 접근성 최소 기준

- 키보드만으로 주요 흐름을 완료할 수 있어야 한다
- 포커스 표시를 제거하지 않는다
- 이미지·아이콘 버튼에 대체 텍스트나 레이블을 준다
- 폼 입력에 label을 연결한다
- 텍스트 대비를 읽을 수 있는 수준으로 유지한다

정량 기준(WCAG 등급 등)은 **확정 필요**.

### 3.5 반응형

- 기준 중단점은 토큰으로 정의하고 임의로 추가하지 않는다
- 가로 스크롤이 생기지 않게 한다. 넓은 표·코드 블록은 자체 영역에서만 스크롤시킨다
- 대상 기기 범위는 **확정 필요** (PRD 8장과 연결)
